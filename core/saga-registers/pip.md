## Summary

SAGA overlays up to two picture-in-picture windows (PIP) on the main screen, each with its own bitmap, format, position and colour key. The original documents PIP 1 only; PIP 2 and the register meanings come from ApolloLib.

## Details

### PIP 1 registers (original)

| Address | Name | Access | Description (original) |
|---|---|---|---|
| `$DFF3D0` | PipXStrt | W | X start |
| `$DFF3D2` | PipYStrt | W | Y start |
| `$DFF3D4` | PipXStop | W | X stop |
| `$DFF3D6` | PipYStop | W | Y stop |
| `$DFF3D8` | PipPtr | W | 32 bit Ptr |
| `$DFF3DC` | PipFormat | W | Colorformat (8bit/16bit/15bit/YUV) |
| `$DFF3DE` | PipModulo | W | Modulo |
| `$DFF3E0` | PipColorKey | W | ColorKey 1000,RRRR,GGGG,BBBB |
| `$DFF3E2` | PipDMARowLen | W | PipDMARowLen |

The original links these rows to a page that doesn't exist; the facts below come from ApolloLib and the ApolloPiP example (SRC).

### PIP 2 registers (SRC, not in the original)

PIP 2 has the same layout as PIP 1, `$20` lower (ApolloLib):

| Address | Register | Same as PIP 1 |
|---|---|---|
| `$DFF3B0` | PIP2 X start | `$DFF3D0` |
| `$DFF3B2` | PIP2 Y start | `$DFF3D2` |
| `$DFF3B4` | PIP2 X stop | `$DFF3D4` |
| `$DFF3B6` | PIP2 Y stop | `$DFF3D6` |
| `$DFF3B8` | PIP2 pointer (32-bit) | `$DFF3D8` |
| `$DFF3BC` | PIP2 format | `$DFF3DC` |
| `$DFF3BE` | PIP2 modulo | `$DFF3DE` |
| `$DFF3C0` | PIP2 colour key | `$DFF3E0` |
| `$DFF3C2` | PIP2 DMA row length | `$DFF3E2` |

Its colour port is `$DFF37C` (see [colour-ports.md](colour-ports.md)). The ApolloPiP example says two PIPs exist from Core 11900 (SRC).

### Register meanings (SRC)

| Register | Meaning |
|---|---|
| X/Y start, X/Y stop | Window position in screen pixels. The example writes X + 16 and Y − 1 to place the PIP exactly over a window. |
| Pointer | 32-bit address of the PIP bitmap |
| Format | Bits 7–0: pixel format; bit 8: transparency on. See the table below. |
| Modulo | Bytes skipped after each row |
| Colour key | Bit 15 = enable, bits 11–8 red, 7–4 green, 3–0 blue |
| DMA row length | Bytes fetched per row = width × bytes per pixel. **0 switches the PIP off.** |

### Pixel formats and transparency

| Format | Value | On PIP | Transparent colour (bit 8 set) |
|---|---|---|---|
| 8-bit indexed | `$01` | Yes | Index `$FF` |
| 16-bit R5G6B5 | `$02` | Yes | `$F81F`: red and blue at maximum (purple) |
| 15-bit 1R5G5B5 | `$03` | Yes | `$7C1F`: red and blue at maximum (purple) |
| 24-bit R8G8B8 | `$04` | No | – |
| 32-bit A8R8G8B8 | `$05` | No | – |
| YUV888 | `$06` | Yes | Not documented |
| YUV444 | `$0E` | Yes | Not documented |

Formats and transparent colours: WDrijver, 2026-11-04. The transparent colour is fixed per format. ApolloLib still marks YUV as not supported on PIP; that is an error in ApolloLib, not in the hardware.

### Two modes (ApolloPiP example, SRC)

- **Overlay:** colour key 0. The PIP is in front of the main screen; with format bit 8 set, pixels in the transparent colour of the format are transparent.
- **Chroma key:** colour key with bit 15 set, for example `$8F0F` (purple). The PIP is behind the main screen and shows only where the main screen has the key colour.

## Differences from AmigaOS / AROS / 68060

- Classic Amiga chipsets have no PIP. Dual playfield is the nearest classic feature, and it is limited to planar bitmaps in Chip RAM.

## Do / Don't

- DO prefer the library calls (ApolloLib) to direct access to these registers: a best practice, not a forced rule (see [prefer-library-calls-for-saga-chips.md](../best-practices/prefer-library-calls-for-saga-chips.md)).
- DO set the DMA row length last: it switches the PIP on.
- DO write 0 to the DMA row length to switch a PIP off.
- DON'T use the 24- or 32-bit formats (`$04`, `$05`) for a PIP.
- DO keep the transparent colour (`$FF` in 8-bit, purple in 15- and 16-bit) out of the PIP image, except where it should be transparent.
